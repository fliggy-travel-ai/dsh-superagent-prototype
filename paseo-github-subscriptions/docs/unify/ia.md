## 1. 设计原则

1. **只做 Paseo 没有的能力。** Paseo 原生已有的功能不出现，也不放跳转按钮（插件不能打开原生设置页），最多在编辑视图中写一句“在 设置 → … 中操作”。
2. **默认视图简洁。** 每张卡片：标题、一句说明、一个开关或一个主按钮、1–2 个关键值。没有表格、阈值、规则明细、统计数字。
3. **细节放在编辑视图。** 点卡片的“编辑”从右侧打开面板，显示详细设置和逻辑说明。窄屏时面板占满屏幕。
4. **只提示异常。** 只有需要用户处理的问题才在页面顶部显示红色或黄色提示，例如“升级通知没有运行”。正常状态不显示提示。
5. 结果不确定时写“未确认”，不写“成功”。不显示令牌原文。

## 2. 结构

一个屏幕“开发自动化”，左侧（窄屏为顶部）四个页面：

1. Provider 与账号
2. 问题答复
3. GitHub 订阅
4. 待办总览

| 页面 | 数据范围 |
|---|---|
| Provider 与账号 | 页头所选主机。顶部一行显示另一台主机是否有需要处理的账号，可切换 |
| 问题答复 | 页头所选主机的设置。蓝牙和声音可以选来源主机 |
| GitHub 订阅 | 页头所选主机 |
| 待办总览 | 两台合看，每条标出主机。某台未响应时顶部提示“只含 Mac mini 的待办” |

### 3.4 待办总览

只收 Paseo 原生界面看不到的待办。两台合看。

筛选：全部、网页提问、网页等待、停滞会话、升级事件、代答未读。

每张卡片：标题（会话名或网页会话名）、来源和主机、等待时长、**一个主操作**。

| 类型 | 主操作 | 次要操作（卡片右上角菜单） |
|---|---|---|
| 网页提问（claude.ai） | 展开选项并提交回答 | 打开原网页 |
| 网页等待（等待输入、用量限制） | 打开原网页 | — |
| 停滞会话 | 打开会话 | — |
| 升级事件（已通知 Grok） | 标为已处理 | 打开会话 |
| 代答未读 | 已读 | 打开会话 |

分页“处理记录”：网页权限点击、代答、升级投递、子会话归并，按时间列出。

## 4. Paseo 原生界面中的插件入口

| 位置 | 放什么 |
|---|---|
| 侧栏顶部 | 单行“开发自动化”：打开上次页面，尾部显示本插件待办角标 N（只统计网页提问、网页等待、停滞会话、升级事件、代答未读，**不含**原生“需要输入”），有异常时同时显示“!” |
| 命令面板（⌘K） | 打开待办总览；切换在线、离线、自动；暂停全部自动化 |
| 主页面各对应卡片与“本机配置”卡片 | 各功能模块由对应卡片开关控制；凭据归入对应功能编辑面板（GitHub 令牌、AdsPower API key、Webhook 凭据状态）；“本机配置”卡片查看配置文件路径与校验结果、导出备份、管理无独立卡片的后台模块开关 |
| 会话输入框胶囊 | GitHub 订阅（现有） |
| 会话时间线 | 额度耗尽自动继续卡片（来自 Claude 额度恢复） |
| 额度面板 | 只提供额度来源数据（Claude 账号、claude.ai 浏览器环境、Antigravity、GLM 等），不放操作 |

## 6. 与 Paseo 原生界面的分工

原生功能清点和证据见 feasibility.md 第 7 节。

| 功能 | Paseo 原生位置 | 插件是否做 | 理由 |
|---|---|---|---|
| Provider 启用、停用、删除 | 设置 → Providers | **不做** | 原生已有 |
| 模型列表、自定义模型 | 设置 → Providers → 模型 | **不做** | 原生已有 |
| Provider 诊断 | 设置 → Providers → 诊断 | **不做** | 原生已有 |
| 添加 Provider（按类型） | 设置 → Providers → 添加 | **部分**：只做“再加一个 Claude 账号”（配置目录、环境变量、登录终端） | 原生只按类型添加，不处理同类型多账号的配置目录和登录 |
| Provider 显示名称 | 无 | **做**（Claude 账号编辑视图中“改名”；名称带额度） | 原生没有改名 |
| Provider 登录 | 无（额度面板只提示“登录过期”） | **做**（打开登录终端，给出链接和授权码输入） | 原生没有登录入口 |
| 额度条、重置时间、刷新 | 额度面板 | **不做** | 原生已有。插件只提供额度来源 |
| 登录过期提醒 | 额度面板 | **不做**（待办中删除“账号与额度”） | 原生已有 |
| 授权请求作答 | 会话时间线 | **不做** | 原生已有，侧栏“需要输入”覆盖全部主机 |
| Paseo 会话中的提问作答 | 会话时间线 | **不做** | 同上 |
| claude.ai 网页提问作答 | 无 | **做**（待办总览） | Paseo 看不到网页会话 |
| 会话状态分组、需要关注 | 侧栏 | **不做**；侧栏“待办 N”只计插件来源 | 避免重复计数 |
| 停滞会话 | 无 | **做** | 原生没有“主会话无活动”判断 |
| 归档 | 会话列表 | **不做** | 原生已有 |
| 系统通知、提示音 | 设置 → 通知 | **不做** | 原生已有。插件的语音播报和 Grok 升级是另一种能力，保留 |
| 主机切换、主机管理 | 页头主机选择、设置 → 主机 | **不做** | 用原生主机选择器 |
| 工作区置顶 | 侧栏 | **不做**；子会话免提醒读取置顶状态 | 原生已有 |
| 计划任务 | 侧栏 → 计划任务 | **不做** | 原生已有 |
| 插件启停、重载、日志（含 Provider 实例） | 设置 → 插件 | **不做**；Provider 实例只显示一行状态 | 原生已有 |
| Agent 配置档 | 设置 → 主机 → Agent 配置档 | **部分**：保留“新建会话默认设置”规则 | 配置档只在手动选用时生效；规则对所有创建请求生效 |
| 网页版 claude.ai 环境注册与配对 | 无 | **做** | 原生没有 |
| 云端会话、Antigravity 等插件 Provider 的账号配置 | 无 | **做** | 插件注册的 Provider |
| 问答模式、蓝牙在场 | 无 | **做** | 原生没有 |
| 升级通知规则 | 无 | **做** | 原生没有 |
| 子会话免提醒规则 | 无 | **做** | 原生没有 |
| GitHub 订阅 | 无 | **做** | 原生没有 |

## 7. 交互原则

- 每个开关的编辑视图写清作用范围：本机、所选主机、或两台。
- 影响 Provider 会话的操作（重载 Provider 实例、添加 Antigravity 账号）先显示会受影响的运行中会话数。
- 模块开关对 Provider 和额度来源要重载才生效，编辑视图中写明。
